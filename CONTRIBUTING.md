# Contributing to Radio Ainur
 
Thank you for your interest in contributing to the Radio Ainur archive.
 
Radio Ainur is a curated music archive. Maintaining consistency, accuracy, and continuity is therefore an important part of the project.
 
This document defines the basic rules for adding, editing, and maintaining archive entries.
  
## Archive Principles
 
The Radio Ainur archive follows five basic principles:
 
 
1. Preserve the original archive.
 
2. Keep metadata consistent.
 
3. Maintain stable references.
 
4. Avoid unnecessary changes to existing entries.
 
5. Treat every new track as part of the wider collection.
 

  
## Adding a Track
 
When adding a new track to the archive, the following information should be checked:
 
 
- Artist name
 
- Track title
 
- Track number, when applicable
 
- Original Telegram post
 
- Relevant metadata
 
- Appropriate categorization
 

 
Before adding a track, verify that it is not already present in the index.
  
## Artist & Track Naming
 
Artist and track names should follow the information used in the original archive.
 
Do not unnecessarily modify:
 
 
- Artist spelling
 
- Track title
 
- Capitalization
 
- Punctuation
 
- Original naming conventions
 

 
When corrections are genuinely necessary, the change should be made consistently throughout the relevant archive.
  
## Track Numbering
 
Existing Radio Ainur track numbers should be preserved.
 
Track numbers represent the chronological history of the archive and should not be reassigned simply to make the index appear sequential.
 
If a track does not have an available number, it should not be assigned an invented number.
  
## Telegram References
 
Where a track has an original Telegram post, the index should link directly to that post.
 
The Telegram reference should remain stable and should not be replaced with an unrelated external source.
 
Example:
 `- #91 — [Disillusioned](TELEGRAM-LINK) `  
## Metadata
 
Metadata should be:
 
 
- Accurate
 
- Relevant
 
- Consistent
 
- Concise
 

 
Only information that contributes meaningfully to identification, discovery, or organization should be included.
  
## Hashtags
 
Hashtags may be used to describe:
 
 
- Genre
 
- Subgenre
 
- Mood
 
- Atmosphere
 
- Musical characteristics
 

 
Hashtags should be relevant to the track.
 
Avoid adding large numbers of generic hashtags simply to increase discoverability.
  
## Music Index
 
The `music-index.md` file is the main structured catalogue of the archive.
 
When adding a track:
 
 
1. Identify the artist's alphabetical section.
 
2. Add the artist if they do not already exist.
 
3. Add the track under the correct artist.
 
4. Preserve existing formatting.
 
5. Include the Telegram reference when available.
 
6. Verify the entry after saving.
 

  
## Formatting
 
The archive uses Markdown.
 
A standard entry should follow the established structure:
 `## Artist Name  - #123 — [Track Title](TELEGRAM-LINK) ` 
For artists with multiple tracks:
 `## Artist Name  - #123 — [Track One](TELEGRAM-LINK) - #145 — [Track Two](TELEGRAM-LINK) - #198 — [Track Three](TELEGRAM-LINK) ` 
Existing entries should not be reformatted without a specific reason.
  
## Editorial Content
 
Editorial descriptions should support the music rather than overwhelm it.
 
When editorial text is added, it should be:
 
 
- Concise
 
- Relevant
 
- Clear
 
- Consistent with the Radio Ainur tone of voice
 

 
Avoid clickbait, exaggerated claims, and generic promotional language.
  
## Updating Existing Entries
 
When correcting an existing entry:
 
 
1. Verify the original information.
 
2. Change only what is necessary.
 
3. Preserve the Telegram reference.
 
4. Preserve the track number.
 
5. Maintain the existing Markdown structure.
 

 
Large-scale restructuring should be avoided unless it is intentionally documented.
  
## Duplicate Prevention
 
Before adding a track, check:
 
 
- Artist name
 
- Track title
 
- Existing track number
 
- Existing Telegram link
 

 
This reduces the risk of duplicate entries.
  
## Pull Requests
 
If external contributors are accepted in the future, pull requests should clearly describe:
 
 
- What was added or changed
 
- Which tracks are affected
 
- Why the change was necessary
 
- Any metadata or link corrections
 

 
Changes should be reviewable and easy to understand.
  
## Commit Messages
 
Commit messages should briefly describe the purpose of the change.
 
Examples:
 `Add new curated tracks  Update music index  Correct Telegram archive links  Fix track metadata  Update archive documentation ` 
Avoid vague messages such as:
 `Update  Changes  Fix stuff `  
## Archive Integrity
 
The archive should be treated as a historical record.
 
Changes should therefore prioritize:
 
**Accuracy → Consistency → Preservation**
 
rather than cosmetic restructuring.
  
## Maintaining the Project
 
When the archive grows, the following should remain synchronized:
 `Telegram    ↓ Original Track Reference  GitHub    ↓ Structured Music Index  Spotify    ↓ Listening / Playlist Discovery ` 
Changes to one layer should not unnecessarily break the relationship between the others.
  
## Contribution Standard
 
A contribution is considered ready when:
 
 
- The artist and track information has been checked.
 
- The Telegram link has been verified when applicable.
 
- Existing numbering has been preserved.
 
- Formatting matches the archive.
 
- Duplicate entries have been ruled out.
 
- Metadata is relevant and consistent.
 
- The change does not unnecessarily alter existing content.
 

  
## Final Principle
 
Radio Ainur is an evolving archive.
 
Every contribution should make the collection easier to understand, navigate, preserve, and revisit.
