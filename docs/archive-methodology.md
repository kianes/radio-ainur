# Radio Ainur — Archive Methodology
 
## Overview
 
The Radio Ainur archive is designed as a structured digital collection rather than a simple chronological list of published tracks.
 
The methodology connects music selection, editorial context, metadata, publishing, indexing, and discovery into a continuous workflow.
 `Discovery     ↓ Selection     ↓ Curation     ↓ Editorial Context     ↓ Metadata     ↓ Publication     ↓ Archive     ↓ Index     ↓ Discovery `  
## 1. Discovery
 
The process begins with discovering music.
 
Discovery can involve different artists, genres, periods, styles, and musical contexts.
 
At this stage, a track is only a candidate for the archive.
 
Discovery does not automatically imply inclusion.
  
## 2. Selection
 
A discovered track is evaluated before becoming part of the collection.
 
Selection considers whether the track has qualities that make it meaningful within the Radio Ainur archive.
 
Possible considerations include:
 
 
- Musical character
 
- Composition
 
- Performance
 
- Production
 
- Atmosphere
 
- Emotional impact
 
- Originality
 
- Cultural context
 
- Relationship to the existing collection
 

 
The purpose of selection is to maintain a curated archive rather than maximize the number of entries.
  
## 3. Curation
 
Curation considers the selected track in relation to the wider collection.
 
An individual track is not treated as an isolated object.
 
Its relationship with other artists, tracks, styles, moods, and musical ideas can contribute to its place within the archive.
 
This allows Radio Ainur to maintain a diverse collection without requiring a single-genre identity.
  
## 4. Editorial Context
 
When appropriate, editorial context is created around a selected track.
 
The editorial layer may provide:
 
 
- An introduction to the track
 
- A description of its atmosphere
 
- A notable musical characteristic
 
- A contextual reference
 
- A reason for discovery
 

 
Editorial writing should remain concise and should support the listening experience.
  
## 5. Metadata
 
Metadata provides the organizational structure of the archive.
 
Depending on the entry, metadata may include:
 `Artist Track Title Track Number Telegram Reference Genre Subgenre Mood Atmosphere Musical Characteristics ` 
Metadata should be accurate, consistent, and relevant.
  
## 6. Track Identification
 
Each archived track should be identifiable through its artist and title.
 
Where available, the original Radio Ainur track number should also be preserved.
 
Track numbers represent the historical order of the archive.
 
They should therefore not be reassigned merely to produce a visually sequential index.
  
## 7. Telegram Archive
 
Telegram functions as the original publishing and chronological archive layer.
 
The original Telegram post provides the direct reference for an archived track.
 
The Telegram archive preserves the publication history of Radio Ainur.
 `Track   ↓ Original Telegram Post   ↓ Chronological Archive `  
## 8. GitHub Index
 
GitHub provides the structured reference layer.
 
The `music-index.md` file organizes the archive primarily by artist and provides direct navigation to the corresponding Telegram posts.
 
This creates a different experience from Telegram:
 `Telegram Chronological Archive  GitHub Structured Index ` 
The two layers complement one another.
  
## 9. Spotify
 
Spotify provides a listening-oriented layer for selected Radio Ainur music.
 
Its purpose is primarily:
 
 
- Listening
 
- Playlist discovery
 
- Continuous music experience
 

 
Spotify is therefore treated as a complementary listening layer rather than the canonical documentation archive.
  
## 10. Cross-Platform Relationship
 
The archive can be represented as:
 `                    RADIO AINUR                          │              ┌───────────┼───────────┐              ↓           ↓           ↓           Telegram      GitHub     Spotify              │           │           │         Publishing    Indexing     Listening         + Archive   + Documentation + Discovery              │           │           │              └───────────┼───────────┘                          ↓                   Music Discovery ` 
Each platform performs a distinct function while remaining connected to the same curated collection.
  
## 11. Indexing Method
 
The main music index is organized alphabetically by artist.
 
The general structure is:
 `Artist   ├── Track   ├── Track   └── Track ` 
Artists are grouped alphabetically to make the archive easier to browse.
 
Individual tracks retain their original identifying information.
  
## 12. Archive Integrity
 
Preservation is an important part of the methodology.
 
Existing entries should not be modified without a clear reason.
 
When an update is necessary:
 
 
1. Verify the original information.
 
2. Preserve the track number.
 
3. Preserve the original Telegram reference.
 
4. Change only the necessary information.
 
5. Maintain the established formatting.
 

 
This helps preserve the historical integrity of the collection.
  
## 13. Adding New Material
 
When a new track becomes part of Radio Ainur, the general workflow is:
 `New Discovery      ↓ Selection      ↓ Curation      ↓ Editorial Context      ↓ Metadata      ↓ Telegram Publication      ↓ GitHub Index Update      ↓ Spotify Selection ` 
Not every track necessarily appears on every platform.
 
Each platform has its own role within the ecosystem.
  
## 14. Archive Maintenance
 
The archive is maintained as an evolving collection.
 
Maintenance includes:
 
 
- Adding new tracks
 
- Correcting verified metadata
 
- Maintaining Telegram links
 
- Updating the music index
 
- Preserving track numbering
 
- Maintaining documentation
 
- Keeping cross-platform references consistent
 

 
The objective is to allow the archive to grow without losing structural consistency.
  
## 15. Quality Control
 
Before an archive entry is considered complete, the following should be checked:
 
### Identification
 
Artist and track title are correctly represented.
 
### Reference
 
The Telegram reference is correct when available.
 
### Structure
 
The entry appears in the correct artist section.
 
### Consistency
 
Formatting matches existing archive conventions.
 
### Duplication
 
The track does not already exist in the index.
 
### Preservation
 
Existing archive information has not been unnecessarily altered.
  
## 16. Archive Evolution
 
The archive is expected to evolve over time.
 
As the collection grows, the methodology should remain stable enough to preserve consistency while allowing the structure to improve.
 
Future changes should be documented rather than silently changing the fundamental organization of the archive.

## Methodology Summary
 
The Radio Ainur archive can be understood as six connected layers:
 `1. Curation    What belongs in the collection  2. Editorial    How the music is introduced  3. Metadata    How the music is identified  4. Publishing    Where the music is originally published  5. Indexing    How the collection is organized  6. Discovery    How listeners find and revisit the archive ` 
Together, these layers turn a collection of published tracks into a structured and maintainable digital music archive.
